Configuration

Installation shape comes from Helm values. Anything a person changes while running it lives in the console, so a policy edit is not a redeploy.

Observability

Metrics are exposed in Prometheus format on the operator's metrics port, and labelled series are created at zero on start-up so a dashboard is not empty until the first event. OTLP export is available and is always additional: if the collector is unreachable, nothing about scanning or admission changes.

OpenTelemetry export switches on the moment a collector is named, and not before. Traces cover the admission path — the span is what answers "why did that pod take four seconds" — metrics mirror the Prometheus set, and logs travel with their attestkeep.log/v1 schema version.

ValueDefaultWhat it does
observability.otlp.endpointemptyThe collector, e.g. http://otel-collector.observability.svc:4317. Empty means no OTLP export at all.
observability.otlp.protocolgrpcgrpc or http/protobuf.
observability.otlp.insecuretruePlain connection, for a collector on the cluster's own network. Set false the moment the endpoint leaves it.
observability.otlp.headersemptykey=value pairs, comma-separated — how a hosted collector takes its API key.
observability.traces.enabledtrueTraces, once an endpoint exists.
observability.traces.sampleRatio0.1A tenth of admission reviews. Admission runs on every pod in the cluster; a full trace of each is a bill rather than a signal.
observability.metrics.enabledtrueMetrics over OTLP, once an endpoint exists. The Prometheus port stays either way.
observability.metrics.intervalMillis30000Export interval, in milliseconds because the OpenTelemetry specification defines it that way.
observability.logs.enabledtrueLogs over OTLP, once an endpoint exists. Stdout keeps its copy regardless.

The same knobs answer to their standard environment names (OTEL_EXPORTER_OTLP_ENDPOINT, OTEL_TRACES_SAMPLER_ARG, OTEL_METRIC_EXPORT_INTERVAL, …) for an installation that configures collectors outside Helm.

The log level is a runtime control in the console, not a deployment setting. Turning up logging to diagnose something should not require a rollout.

What lives in the console instead

  • Policies, and the exceptions to them, with an owner and an expiry.
  • Notification destinations.
  • Users and single sign-on.
  • Log level.
  • Evidence packages.

The dividing line: a Helm value describes how the installation is shaped, and everything a person changes while operating it belongs where they can change it without a deploy.
